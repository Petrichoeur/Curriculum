Multiplication Matricielle Massive (GEMM)

Un réseau de neurones (MLP, CNN, LLM / Transformer) repose à 90% sur une seule opération mathématique : Y = W * X + b. Dans un modèle de plusieurs milliards de paramètres, cela représente des milliards de multiplications scalaires totalement indépendantes les unes des autres. Le CPU traite les calculs par petits paquets séquentiels. Le GPU, grâce à son architecture SIMT (Single Instruction, Multiple Threads), distribue ces millions de multiplications simultanément sur des milliers de cœurs CUDA et Tensor Cores en un battement d'horloge.

Le Goulet d'Étranglement : DDR5 vs HBM3

La puissance brute de calcul ne sert à rien si les cœurs passent leur temps à attendre les données. C'est le Memory Wall. Alors qu'une mémoire vive classique (DDR5) plafonne à environ 60-90 GB/s de bande passante sur un bus 64/128-bit, la mémoire GPU (VRAM HBM3 / GDDR6X) empile les puces en 3D avec des bus de 1024 à 4096-bit, atteignant plus de 3000 GB/s (3 TB/s). C'est ce flux colossal qui permet d'alimenter les LLMs en phase d'inférence (Memory-Bound).

Warp Divergence : Pourquoi le CPU gagne sur le code à embranchements

Le GPU n'est pas "meilleur" que le CPU dans l'absolu. Sur un code comportant de nombreux if / else / switch imprévisibles, le CPU excelle grâce à ses unités de Branch Prediction (prédiction à plus de 95%) et à son exécution spéculative. À l'inverse, sur GPU, les cœurs d'un même groupe (Warp de 32 threads) partagent le même pointeur d'instruction : si un thread prend la branche A et un autre la branche B, le GPU est forcé de sérialiser l'exécution (exécuter A pendant que B attend, puis exécuter B pendant que A attend). C'est la Warp Divergence.

GPU-as-a-Service & FinOps : Rentabiliser les clusters IA

Un GPU moderne (H100/A100) coûte plusieurs dizaines de milliers d'euros. Dans une infrastructure bancaire ou entreprise, laisser un GPU à 15% d'utilisation est un gouffre financier. L'ingénierie MLOps met en place des plateformes GPU-as-a-Service : partitionnement matériel (Nvidia MIG - Multi-Instance GPU), fractionnement logiciel via Kubernetes et Run:AI, et ordonnancement dynamique des charges d'entraînement et d'inférence pour garantir un taux de saturation maximal et optimiser le ROI énergétique (Green IT).
